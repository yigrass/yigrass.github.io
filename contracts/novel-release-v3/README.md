# 小说成品约定 v3

本约定提供给独立小说项目，用于实现自己的发布导出工具。网站项目 yigrass.github.io 只接收已完成的发布文本与素材，不参与写作、校对、排序或地址设计。合同标识为 `novel-release-v3`，清单使用 `schemaVersion: 3`。本版替代 v2，不提供旧清单或旧地址兼容。

## 交付边界

小说项目在自己的目录导出完整的 `dist/`，导出过程不得写入网站项目。接入时把该目录的内容完整复制到网站的 `releases/<接收目录>/`，可以先删除网站中该书的旧成品目录，再复制新目录。接收目录名不决定书名或公开地址。每章只保留当前发布文件，整包只有一份 `release.json`，它始终列出当前完整公开内容；增加第 16 章时，清单仍包含已发布的前 15 章。修订和撤下由源头重新导出后整包替换。

网站保留并发布包内文件的原始字节，包括清单未引用的文件。因此导出工具应只输出可以公开的最终内容，不带草稿、笔记、缓存或开发代码。网站生成的 SHA-256 收据用于识别本次成品，不另存可阅读的历史版本。

## 清单结构

字段结构以随包的 [release.schema.json](release.schema.json) 为准；该 Schema 供生产者使用，网站不运行 Schema 校验器。最小结构如下，完整的两卷五章示例见 [example/release.json](example/release.json)。

```json
{
  "schemaVersion": 3,
  "kind": "novel",
  "id": "sh-tales",
  "icon": "images/sword.png",
  "readme": { "file": "README.md" },
  "volumes": [
    {
      "id": "case-greedy",
      "readme": { "file": "volumes/greedy.md" },
      "chapters": [
        { "id": "prologue", "file": "chapters/opening.md" },
        { "id": "ep-05", "file": "chapters/whatever-name.md" }
      ]
    }
  ]
}
```

每本书至少提供一卷，整书和每卷各有一个 README 文档；即使只有一卷，也保留卷层级。`file` 是成品根目录内的相对文件路径，不要求 README 文档的文件名真的叫 README.md。所有 README 和章节必须是 UTF-8 的 `.md` 文件；没有明确的另行约定，不交付 TXT、HTML、PDF 等正文格式。插图可放在 `images/` 等包内目录。`icon` 为本书图标的相对路径，建议提供适合缩放的方形 PNG；它同时用于磁盘文件、窗口标题、任务栏及目录书名。

## 标识、地址和顺序

`id` 是生产者给出的原始地址段，不是显示标题。书、卷、章各提供自己的标识；每段须适合直接用作 URL 的单个路径段及静态目录名，不含 `/`、`\`、`?`、`#` 等路径控制字符，不使用 `.` 或 `..` 作为整段。建议采用可读的小写字母、数字和短横线；这不是数字编号要求。`case-greedy`、`prologue` 完全合法，不必带序号，也不必与文件名或标题有关。

书标识在网站中唯一，卷标识在本书中唯一，章标识只需在所属卷中唯一。生产者负责这些条件；网站不查重、不修正、不推测或重编号。不同卷可以同时有 `ep-05`。本书地址来自清单 `id`，网站只在前面加所属虚拟磁盘的路径：

| 文档 | 示例公开地址 |
| --- | --- |
| 整书 README | `/file-explorer/a-floppy-disk/sh-tales/` |
| 第二卷 README | `/file-explorer/a-floppy-disk/sh-tales/case-02/` |
| 第二卷第五章 | `/file-explorer/a-floppy-disk/sh-tales/case-02/ep-05/` |
| 第一卷中同名章节 | `/file-explorer/a-floppy-disk/sh-tales/case-01/ep-05/` |
| 不带数字的命名 | `/file-explorer/a-floppy-disk/sh-tales/case-greedy/prologue/` |

`volumes` 的数组顺序决定卷顺序，每卷 `chapters` 的数组顺序决定章顺序。目录和前后翻章均采用这个顺序，不对标识、文件名、标题里的数字进行排序。网站不进行发布内容的业务校验；JSON 语法错误、必需结构无法读取、文件不存在仍会造成正常的读取或构建错误。构建工具保留文件系统边界保护，拒绝越出成品目录的读取和符号链接，这不涉及内容、编号或排序检查。

## 标题和目录行为

每个 README 和章节应当有一个表示本页标题的 H1。网站使用 Markdown 解析器找到的第一个 H1，取其可见文字作为目录标题；代码块内的 `#` 不算标题，行内加粗等格式符不显示为字符。标题中原有的标点和文字保留，不依据文件名或清单字段生成标题。没有 H1 时网站不猜测替代标题，生产者应在导出阶段保证标题完整。

整书 README 的 H1 用于书名，卷 README 的 H1 用于卷名，章节 H1 用于章名。清单不需要重复提供 `title`。目录显示书 → 卷 → 章，README 不显示为单独文件；点击书名或卷名只打开对应 README，加减号单独负责折叠与展开。目录长标题单行省略，完整标题保存在悬停提示中。

## Markdown 显示

网站采用 markdown-it 15.0.2，与 VS Code Markdown 预览使用同一种解析核心；不包含 VS Code 的预览样式和额外扩展。启用默认 Markdown 语法、表格、删除线及自动链接；关闭原始 HTML、智能标点替换和普通单换行的强制换行。代码块显示为等宽文本，目前没有语法着色。正文默认字体、行距、边距和颜色由网站通用阅读器提供，每书内部配置以后另行约定。

生产者可使用标题、段落、强调、引用、多级列表、分隔线、表格、代码和图片等 Markdown 语法。空行分段；需要显式换行时使用 Markdown 硬换行。原始 HTML 作为文字显示，危险链接协议由解析器拒绝。

Markdown 中相对图片和链接均以**成品根目录**为基准，而不是当前 `.md` 所在目录。例如任何一章都用 `![插图](images/scene.png)` 引用包内插图，用 `[下一章](chapters/next.md)` 指向清单中登记的正文文件。站内正文链接转为对应的书/卷/章地址，HTTP(S) 外部链接在新标签页打开。图片文件不需要额外登记；导出工具负责引用正确。站点不替生产者检查未引用素材或正文中的资源链接。

## 生产者导出工具的职责

工具应从源头生成一份完整的最终成品：确定书/卷/章标识与顺序，输出 `.md` 正文及各级 README 的 H1，复制所需图标和插图，最后生成完整清单。生产者可按需要使用本 Schema 或增加本项目自己的校验。网站不附带或调用小说校验器，不依赖生产者源码路径，也不运行生产者构建器。

交付示例中的两卷五章包含重复的卷内 `ep-05` 和一个 `prologue`；第二章保留长文本以测试滚动。示例是通用测试文本，可用来理解结构，不要求真实作品采用相同文件名或编号。
