# 小说成品约定 v1

Contract ID: novel-release · Schema version: 1 · Consumer: yigrass.github.io · Date: 2026-09-23

这份约定供独立小说项目制作导出工具使用。小说项目负责写作、修订、选定公开章节和生成自己的 dist；网站只接收最终文本及插图，提供桌面入口和通用阅读器。请将本目录整体交给小说项目，其中包含字段 Schema、独立校验器和完整示例，不需要把网站源码作为小说项目的依赖。

## 交付目标

每次导出都得到一份完整、可独立接收的当前公开成品。一本小说只有一份 release.json，每章只有当前正文文件，没有章节版本目录、历次清单或增量操作日志。用户已明确选择这一覆盖当前成品的管理方式；修订在源头完成后重新导出，网站中不直接编辑作品文本。

第 1 次发布 15 章，release.json 就列出全部 15 章；第 2 次发布第 16 章，清单列出全部 16 章。导出工具可以内部按变化优化处理，但最终 dist 必须包含完整当前清单和全部引用文件，接收方不应依赖旧目录补齐内容。

```text
dist/
├─ release.json
├─ chapters/
│  ├─ chapter-001.txt
│  └─ chapter-002.txt
├─ images/                         # 可选，只放被清单引用的插图
│  └─ scene-001.png
├─ LICENSE.txt                     # 可选，成品的许可说明
└─ NOTICE.txt                      # 可选，所用素材的署名与声明
```

交付时复制的是 dist 中的内容。网站中落点为 releases/<小说 id>/，不再包一层 dist。例如 releases/story-a/release.json，而不是 releases/story-a/dist/release.json。文件名固定为 release.json，不需要 publications 目录或 release-001.json。

## release.json

字段类型、必填项和允许值以本目录的 release.schema.json 为机器权威来源。使用 JSON Schema 的工具可以直接读取它；跨字段、文件内容和目录完整性由 validate.mjs 补充校验。不要根据下面的说明另外放宽字段或添加未约定字段。

```json
{
  "schemaVersion": 1,
  "kind": "novel",
  "id": "example-book",
  "title": "示例小说",
  "author": "示例作者",
  "language": "zh-CN",
  "description": "用于检查导出格式的示例。",
  "status": "ongoing",
  "chapters": [
    {
      "id": "chapter-001",
      "title": "第一章",
      "file": "chapters/chapter-001.txt",
      "illustrations": [
        { "file": "images/scene-001.png", "alt": "示例插图", "afterParagraph": 1 }
      ]
    },
    {
      "id": "chapter-002",
      "title": "第二章",
      "file": "chapters/chapter-002.txt"
    }
  ]
}
```

schemaVersion 表示成品格式的版本，始终填写数字 1；它不表示小说写到了第几次发布。kind 固定为 novel。id 是小说的稳定标识，须与网站作品目录登记的 id 一致；采用小写字母开头的小写字母、数字和连字符。title 是作品标题，文件后缀和所属磁盘由网站目录配置，不写入小说标题。

status 取 ongoing（连载中）或 completed（已完结），不影响已公开章节的可读性。author、language、description 可选，当前阅读器不承诺展示所有可选元数据。chapters 至少有一章；尚无公开章节时不要导出一个空发布包供网站登记。

chapters 数组顺序就是阅读顺序，不根据文件名、章节 id 或标题再次排序。每章 id 必须唯一，建议使用稳定值，例如 chapter-001；title 是读者看到的章节标题；file 是正文在包内的路径。两个章节不能引用同一正文文件。章节内容发生修订时保留相同的 id 和路径，重新导出该文件即可。

## 正文与段落

v1 采用 UTF-8 纯文本 .txt；允许 UTF-8 BOM，允许 LF、CRLF 或 CR 换行。正文必须有非空内容，不能包含 NUL 字符。HTML 或 Markdown 标记会按普通文字显示，不执行、不解析；如果源稿是 Markdown，导出工具应按作品需求转换成最终纯文本，不能假定网站会渲染标题、链接或强调语法。

阅读器将换行统一成 LF，去掉正文首尾空白，再用一个或多个空行分隔段落；只含空格或制表符的行也算空行。段内单个换行保留。建议一个自然段写成一行，相邻段落空一行；不要为源编辑器的列宽硬折行。

章节标题已在清单中提供并用于章节选择器，正文是否重复写标题由作者决定，网站不会自动删除正文中的标题。正文中包含的尖括号等字符按文本展示，不会当作网页代码。

## 可选插图

没有插图时省略 illustrations 和 images 目录即可。插图使用 PNG、JPEG（.jpg 或 .jpeg）或 WebP，图片字节不由网站改写或重采样。每项必须提供包内 file、非空 alt 替代文字和 afterParagraph。

afterParagraph 使用上述分段规则计数：0 表示正文第一段之前，1 表示第一段之后，以此类推；不能超过本章段落数。同一位置的多张图片按 illustrations 数组中的顺序展示。插图宽度随阅读区域缩放并保持比例。某张图可以由多个章节重复引用，但它仍必须包含在成品中。

校验器检查文件存在、扩展名与图片格式签名相符；这不是完整的图像解码或视觉质量检查。导出项目应检查图片实际可打开、文字替代说明正确，接入后再检查阅读效果。

## 文件与发布边界

所有路径均相对于 release.json 所在目录，使用正斜杠。正文路径以 chapters/ 开头并以小写 .txt 结尾；图片路径以 images/ 开头并使用上述小写扩展名。正文与图片路径采用小写 ASCII 字母、数字、连字符、下划线和点，每段以字母或数字开头；允许普通子目录。不使用中文或空格作文件路径，但作品和章节标题可正常使用中文。

禁止绝对路径、盘符、反斜杠、网址、查询参数、百分号转义、`.` 或 `..` 路径段、尾随点、Windows 保留设备名，以及大小写不同但实际重名的路径。输入目录和文件不能是符号链接或目录联接。成品中的路径不得指向小说项目的源码、电脑上的其他位置或网站自身的素材目录。

除 release.json、引用的正文和插图，以及可选 LICENSE.txt、NOTICE.txt 外，不接收其他文件。草稿、大纲、未发布章节、原始美术、编辑器配置、日志、导出脚本和旧版残留都放在成品外。空目录没有发布意义，也不要用来表达未来章节。

如需署名或许可证，源头项目将必要文字放在上述两个可选文件中，连同成品交付。网站不会替作品推断授权。发布包内的文件都应视为允许公开，不能依赖“没有在页面上显示”来隐藏内容。

## 校验命令

校验器需要 Node.js 24 或更新版本，没有第三方依赖，也不联网。将本约定目录复制到小说项目自己的 tools/novel-release-v1/ 后，可以运行：

```powershell
node tools/novel-release-v1/validate.mjs ./dist example-book
```

将 example-book 换成小说 id。成功时退出码为 0，标准输出为 JSON，包含章节数、manifest、各文件 SHA-256、字节数和整包摘要；失败时退出码非 0，并给出原因。校验器只读，不删除、修改或自动修复成品。校验日志应保存到 dist 之外，否则会成为不允许的额外文件。

只想验证本目录自带的例子，可在本约定目录运行：

```powershell
node validate.mjs ./example example-book
```

本目录的 example 是完整有效成品，可以复制到独立临时目录验证。示例插图复用了桌面项目已有的光盘图标，仅展示文件格式和插图位置，不是作品实际插画。

## 给小说项目的导出工具要求

1. 从作者明确选定的公开章节生成完整清单，保留指定顺序和稳定章节 id，不从目录里猜测哪些草稿应公开。
2. 将正文转换为约定的最终 UTF-8 纯文本，并复制需要公开的插图，建立正确的相对路径和段落插入位置。
3. 在小说项目自己的临时输出目录组装完整成品，运行本校验器或同等严格的验证，通过后再替换该项目的 dist，避免导出失败留下半套成品。
4. 重建时移除不再发布的旧文件，保证 dist 自包含。导出工具不主动写入网站仓库，也不执行网站的 Git 或部署操作。
5. 为编辑错误、缺失图片、重复章节等失败返回明确错误和非零退出码。成功后提供 dist 的位置，供用户复制或另行接入。

网站接入时可先删除 releases/<id>/ 再复制完整成品，或者使用具有相同行为的替换工具。这里的整目录替换由用户执行，本校验器没有删除功能。复制后网站再次校验并构建自己的 dist；接受失败时先修正源头导出，不在网站中临时修改正文绕过检查。

## 追加、修订和撤下

追加第 16 章时，导出完整的第 1～16 章及新的当前 release.json；原有章节路径不变。修订第 5 章时，源头替换其最终正文，导出目录里依旧只有一个 chapter-005.txt。撤下章节或插图时，从清单及成品目录同时移除。每种操作都能通过一次完整复制接入，不要求网站知道此前发布过什么。

正文文件与清单被替换后，网站不提供历史版本入口。若仓库使用 Git，旧内容可能仍在提交历史中；此约定不要求清除 Git 历史。新增格式能力时升级合同并明确接收方支持情况，不能把自定义字段悄悄加入 v1。
